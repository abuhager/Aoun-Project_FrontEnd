# ADR-001: CSP nonce واستراتيجية الرندر

الحالة: **مقبول مؤقتًا — يحتاج قياس Production**  
التاريخ: 2026-09-08

## القرار

نحتفظ بـCSP صارمة مع nonce فريد لكل طلب، ولذلك يبقى `RootLayout` ديناميكيًا
باستخدام `connection()`. لا نزيل nonce ولا نضيف `unsafe-inline` للحصول على
static rendering قبل قياس الأثر ووضع threat model للمسارات العامة والحساسة.

أزيل الاعتماد على Google Fonts وقت البناء والتشغيل، وأصبحت خطوط Tajawal وCairo
وMaterial Symbols محلية. هذا يقلل أحد أسباب التباين الشبكي، لكنه لا يغيّر قرار
الرندر الديناميكي.

## بوابة أي تغيير لاحق

يجب تسجيل p50/p95 لكل من TTFB وLCP وINP على preview مماثل للإنتاج، ثم مقارنة:

1. الوضع الحالي: nonce لكل طلب.
2. route group عام يستخدم CSP hashes/static-compatible، مع بقاء المسارات
   المحمية على nonce.

لا يُقبل البديل إلا إذا بقيت اختبارات CSP وXSS ناجحة، ولم تُحجب سكربتات Next،
وكان تحسن p95 ملموسًا. الرجوع هو إعادة كل المسارات إلى layout الحالي.
